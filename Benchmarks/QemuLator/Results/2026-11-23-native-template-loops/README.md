# Native control flow for string and floating-point FOR loops

Implemented call-free native control flow using lib537's memory-counter FOR/NEXT
protocol. The new path retains counter, captured END/STEP and iterator state in
memory across helpers. Existing register-retaining integer loops remain selected
by their established planner. The optimization is enabled by `--native-regions`;
`--no-native-regions` disables it. `--no-regalloc` retains this memory-counter
path while disabling register allocation and pinned loops. `--no-hir-opt` controls
HIR rewriting independently. The legacy Turbo peephole pass remains enabled.

## Safety and implementation

`TurboNativeTemplateLoops.fs` runs after HIR lowering and before straight native
region selection. It requires an existing HIR binding certificate, matching
integer range FOR/NEXT, known descriptor ranks for indexed operands, at most 256
body records, no external entries and forward local IF branches. A typed maths
stack audit requires empty, equal stacks at every join and loop boundary.
Procedure/resident calls, nested loops, handlers, nonlocal transfers, mismatched
proofs and unknown instructions retain the existing fallback. Boolean operations
alone never take a loop away from the integer register allocator.

The path reuses genuine native library templates; it changes neither lib537 nor
the machine-code generator. Integer arithmetic and numeric arrays share the
existing checked/proven lowering. String indexing keeps its original checks.
Native append and simple LEN omit checks present in P mode, so those two
operations use short threaded sections with the original P templates. Both loop
exits restore P mode. No register/address is assumed live across helpers and no
new arithmetic overflow policy is introduced.

Effect analysis recognizes exact unary LEN/CODE/CHR$ and the canonical MID$/RIGHT$
slice patterns emitted inline by the backend. Arguments retain their effects,
allocation and failure flags. User overrides, wrong arities and general slice
calls remain opaque. This precise classification is included in the before/after
measurements; it allows valid loop binding proofs in the string workloads.
