# Structured SuperBASIC 2.8.0 in SB

SB's managed SSB preprocessor supports the record language described by the
SSB 2.8.0 README and `Docs/Records-Development.md` in Structured Super Basic.
The reference implementation remains Timothy Swenson and Norman Dunbar's QL
translator. SB implements the transformation in F#; it does not launch that
translator or require a QL emulator.

```basic
TYPE point
  x
  y
END TYPE

DIM origin AS point, duplicate AS point
makePoint origin, 3, 4
duplicate = origin
PRINT duplicate.x; ","; duplicate.y
STOP

DEFine PROCedure makePoint(output AS point, VAL xValue, VAL yValue)
  output.x = xValue
  output.y = yValue
END DEFine
```

Save this as `.ssb` and use the existing SB command line, for example
`dotnet run --project SB/SB.fsproj -- example.ssb`.

## Supported language

- Top-level, nominally typed `TYPE` declarations, forward references, embedded
  scalar records, floating point/integer fields, bounded strings and array fields.
  Recursive embedded layouts and embedded record arrays are rejected.
- `DIM` global records and record arrays, and per-invocation `LOCal` records and
  arrays. Outer bounds can be runtime expressions. Every declaration clears the
  complete allocation, including index zero.
- Dotted fields, embedded record views and whole-record assignment, including
  array-field contents. A copy captures destination selectors first, then source
  selectors, before any field is written. Whole record arrays cannot be copied
  with a single assignment.
- Writable record parameters and whole-record-array parameters, including in
  scalar-returning functions. Functions cannot return records. Scalar `VAL`
  arguments and explicitly parenthesized scalar arguments preserve value semantics.
  Constructors use explicit output record parameters; no implicit record result
  or copy-in/copy-out parameter is introduced.
- One-dimensional global `POOL` declarations with `<name>_new%` and `<name>_free`.
  Zero is null, allocation initializes a slot, and redimensioning resets the pool.
  Exhaustion, invalid handles and double frees stop with a diagnostic.
- Multiline/simple inline conditionals, colon-separated statements, inline loops,
  and SELECT arms. Generated operations remain inside the original branch or
  loop. SELECT expansion captures its selector and handles exact matches, ranges
  and REMAINDER. Nested inline IFs and explicitly closed inline loops require
  multiline form, matching the reference translator's conservative parser.

Expansion happens after active includes/conditionals are frozen and before labels
are numbered. Strings, DATA and remarks are not treated as dotted field references.
Generated identifiers are collision-checked and `rec_` is reserved only in extended
programs. Record names must retain one nominal type and rank throughout a program.
Effectful expanded argument selectors must be split into scalar temporaries.

## Profiles and configuration

`SSBRECPROFILE=TURBO509` is the default. It rejects selected record-array elements
as typed arguments; use an explicit standalone work record and copy it back.
Standalone records and complete arrays remain supported.

`SSBRECPROFILE=SBASIC` additionally accepts selected elements containing only scalar
fields, including bounded strings. Elements with array fields remain unsupported.
This profile is not an assurance that Turbo can compile its output.

`SSBRECITEMS` defaults to 256 and accepts integers from 32 through 1024. It limits
declaration/layout tables. Source logical lines are limited to 1,000 characters
and extended lines to 256 lexical tokens. Physical backing arrays have at most
eight dimensions, including a string's capacity axis. Expanded routine parameters
and locals have a limit of 64 each. Outer array bounds are integers from 0 through
32767; pool bounds are from 1 through 32767.

Existing `SSBINPUT`, `SSBOUTPUT`, `SSBSTART`, `SSBINC`, `SSBWORK`, `SSBWORK2`,
`SSBOVER`, and `SSBIGNORE_BLANKS` settings remain available. Generated BASIC line
numbers are from 1 through 32767, with positive increments. Includes can nest
through 19 input files; conditional nesting is limited to 32 and must balance
within each file. Source-relative include resolution is available on modern hosts.

The managed pass uses memory rather than QL spool devices, channels or executable
dataspace reservations. `SSBRECWORK` and the QL batch-log setting are not required;
SB reports translation errors through its normal compiler diagnostics.

The standalone `SSB.Ssb.run` path validates the full translation before replacing
an existing output. Authorized replacements retain the old output as `_bakN`.
Pipeline translation stays in memory and writes no intermediate BASIC file.

## Verification and runtime scope

`SBTests/Ssb280Tests.fs` runs upstream programs through SB's actual parser,
semantic analysis, HIR lowering and interpreter. It covers records, arrays,
pools, recursion, value/reference semantics, aliases, selectors, generated-name
collisions, configuration, line numbering and long-line literal integrity. The
upstream rejection fixtures are also exercised. Fixtures are copied into
`SBTests/Fixtures/Ssb280`, so testing does not require the separate SSB checkout.

The QDOS test result channels are redirected to SB's console in these tests.
Comparisons normalize SB's existing PRINT argument spacing; this change does not
implement QL console formatting or hardware/environment emulation. Other SB
runtime/backend limitations still apply to the resulting ordinary BASIC.


## Correctness regression coverage

`SBTests/SsbCorrectnessTests.fs` covers the regressions reported against the
managed SSB implementation. Ordinary statements before inline IF/FOR constructs
preserve the rest of the line inside that condition or loop. REMark tails remain
opaque after colons and THEN, label scanning accepts identifiers such as `remove`,
and `#ENDIF` accepts trailing whitespace. Ordinary parameters named `val` or `as`
and procedures named `type` do not activate record syntax. DIM/LOCal declarations
can be followed by another statement on the same line, ON GOTO remains a statement
inside SELECT, and preserved blank/colon lines survive record expansion.

SELECT exact matches, string ranges, REMAINDER and selector capture also work in
ordinary BASIC through shared AST-to-HIR lowering. A selector is evaluated once;
generated record argument captures use distinct temporaries across source lines.
Explicit ON arms retain their subsequent body lines. Parenthesized scalar actuals
pass by value with or without records, including a sole procedure argument.
MANIFEST strings retain their string type even when their contents look numeric.

A single string character supplied to a flexible user-function parameter, such as
`isvowel(word$(i))`, passes its value. It cannot supply an explicit REFERENCE
parameter because the runtimes do not provide a reference cell for that character.
Bare string-character procedure actuals retain their existing reference behavior
and are rejected; parenthesize the actual to pass its value.
Generated C and C# execution tests cover string-character calls, value arguments,
MANIFEST strings and SELECT matching. Generated record guard failures retain their
own diagnostic; an ordinary STOP escaping a routine does not append unrelated
previous output.

Output backup retention and declaration-time clearing remain intentional. The
repeated-declaration regression checks that existing record array fields reset.
